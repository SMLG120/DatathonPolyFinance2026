## Reproduction procedure

Upload `dist/cloudshell-release.zip` through CloudShell Actions / Upload file. Extract it into a fresh directory and run from `cloudshell-release/`:

```sh
python3 cloudshell_release.py prepare
python3 cloudshell_release.py status
```

`prepare` uploads snapshots and artifacts and creates a CloudFormation change set; it does **not** execute it. Review the changes, validation events, exact frontend origin, lack of replacement/removal, and the scoped API/worker role permissions before execution. The API gains invocation of the configured Bedrock inference profile and snapshot/policy access. Follow the applicable action-time browser confirmation requirement for security-sensitive permission changes.

```sh
python3 cloudshell_release.py execute --change-set-id '<reviewed ARN>'
python3 cloudshell_release.py status
```

After `UPDATE_COMPLETE`, run `python3 cloudshell_smoke.py`. The access code is obtained from SSM inside CloudShell and stays in memory. The smoke test requires the real interpreter and `MODEL` investigation mode; a deterministic fallback cannot count as success.

Then `python3 cloudshell_release.py host`, inspect the returned Amplify job until it succeeds, and verify the hosted browser flow without `fixtures=1`. Confirm the API URL stayed unchanged before using the prepared frontend bundle. The initial uploaded helper refused every conditional replacement; the local helper now permits only the reviewed SAM authorizer invocation permission. This release executed the exact approved change set through boto3 after manual review.
